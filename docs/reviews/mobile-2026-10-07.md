# Android / iOS bug review and comparison

Reviewed `main` at `74af6be`, focusing on authentication, navigation, checkout, playback, catalogue, series and the new splash. This is a source review plus an iOS simulator compilation, not an exhaustive device test. Mobile files were not modified. Existing `.claude/worktrees` checkouts were left intact.

## Fix follow-up

All six findings were addressed in the subsequent mobile fix pass. See [implementation and regression results](mobile-fixes-2026-10-07.md). The findings and comparison below describe the original reviewed commit.

## Findings

### P2 — iOS signs the viewer out on temporary refresh failures

`apps/ios/CinneTemple/Core/Session/SessionStore.swift:232–236` catches every refresh error and calls `signOut()`, which removes both tokens and the cached user. An expired access token followed by an offline connection, 429 or 503 permanently discards an otherwise valid session. This can also interrupt a long film because playback heartbeats invoke the same refresh function. Preserve credentials for transient failures; only clear them after a definitive rejection.

### P2 — Android also clears credentials after a transient refresh failure during restore

`apps/android/app/src/main/java/com/cinnetemple/app/core/network/TokenAuthenticator.kt:88–92` catches the refresh `IOException` and returns null. OkHttp then returns the original `/auth/me` 401, which `SessionStore.kt:70–74` treats as definitive and clears. A cold start with a valid persisted refresh token and a temporarily failing refresh endpoint therefore logs the user out. The authenticator also treats refresh 429 as definitive (`executeRefresh` only exempts 5xx). Propagate a transient failure separately from the original 401 and retain tokens on 429.

### P2 — Android movie and trailer players never request audio focus

`apps/android/app/src/main/java/com/cinnetemple/app/ui/feature/watch/SecurePlayer.kt:140–146` and `ui/feature/title/TrailerPlayer.kt:129` build ExoPlayer without media audio attributes/focus handling. Starting a film while music is playing can leave both audible; the app also lacks the expected focus-loss handling. iOS explicitly activates `.playback`/`.moviePlayback` and releases its audio session. Use Media3 media/movie audio attributes and audio-focus handling for the Android film/trailer players. The unmerged `feat/android-parity` branch already applies a movie-playback helper.

### P2 — iOS search corrupts terms containing an ampersand

`apps/ios/CinneTemple/Core/Networking/CatalogueAPI.swift:33–35` uses `.urlQueryAllowed` to encode an individual query value. This character set leaves `&` unescaped. Verified with Foundation: `Love & War` becomes `q=Love%20&%20War`, parsed as `q=Love ` plus a second query parameter. Android Retrofit's `@Query` encodes the value correctly. Construct the URL using `URLComponents`/`URLQueryItem` or encode the value with the reserved query separators excluded.

### P2 — Android splash uses a video surface that cannot reliably fade on older supported devices

`apps/android/app/src/main/java/com/cinnetemple/app/ui/splash/AnimatedSplash.kt:112–119` constructs the default SurfaceView while Compose animates the wrapper opacity. SurfaceView does not support intermediate alpha before Android 14, so the intended reveal/exit is not reliable across the app's API-24+ range. Use a TextureView for this short animated overlay. A corresponding fix exists on `feat/android-parity`, not `main`.

### P3 — iOS splash observer is never removed

`apps/ios/CinneTemple/Features/Splash/AnimatedSplashView.swift:58–60` discards the token returned by the block-based notification registration. NotificationCenter retains the registered closure after the splash exits. Keep/remove the token on finish and disappearance, or use a scoped notification subscription. This is a lifecycle/resource issue, rather than an accumulating per-screen leak in ordinary single-launch use.

## Comparison

| Area | Android on main | iOS on main |
|---|---|---|
| Catalogue, search, watchlist | Present; Retrofit query encoding | Present; ampersand encoding bug above |
| Tickets, purchase verification, gifting | Present | Present |
| Movies and series episodes | Present; per-episode watch-once | Present; per-episode watch-once |
| Playback progress, watermark, expiry | Present | Present |
| Media audio ownership | Missing on main | Explicit playback audio session |
| Biometric gate | Device biometrics / credential fallback | LocalAuthentication biometric gate |
| Offline startup | Returns to sign-in UI; tokens normally retained | Cached-user offline phase |
| Refresh outage handling | Session loss during restore | Session loss on any refresh failure |
| Push notifications | Notification feed exists; no FCM service found | Push manager and application delegate wiring |
| Coins / wallet / funding | Not on main; implemented on unmerged Android branch | No corresponding viewer screens found |
| Producer dashboard | No native viewer screen found | No native viewer screen found |
| Minimum platform in project | Android API 24 | iOS 26.5 deployment target |

Missing features are parity gaps, not automatically defects. In particular, the wallet and producer commits on main mainly concern web/backend, so their presence in Git history does not mean both native apps include those screens.
